# Locally addressable Buildx image references

The historical cd6 ARM workflow found a real supported-tool mismatch: Docker CLI 29.1.4 / buildx 0.30.1 against Desktop Engine 29.9.3 reports both config and manifest digests, but that store rejects `docker image inspect <config>` while the manifest reference resolves to the tagged image. Native cd6 returned the unaddressable config reference and null size. `../../buildx-containerd-linux-arm-inspect.json` is the exact independent raw reproduction with the native `BUILDX_NO_DEFAULT_ATTESTATIONS=1` setting, full metadata, tagged image and both actual candidate inspections. It records a 12,787,027-byte addressable image. This is a native compatibility fix, not a limitation relabelled as source behavior.

The frozen corrected production file is `native/src/executor/build.rs`, SHA `8e696aa15b2edc0b21a2c8bcd68370c316c7573cdd07e0d26b186432e5a881df`. Local load/tar outputs inspect at most two distinct metadata candidates, config first and manifest second; the first parsed size selects its exact addressable reference. A valid zero size preserves config priority. If both inspections fail, the original metadata reference and null size remain, preserving successful-build behavior when an image disappears externally. Push/cache-only outputs retain metadata behavior and perform no local inspections. There is no tag fallback, shell call or global Docker configuration change.

The exact raw-pair regression failed against the previous resolver and passed after correction. Five focused unit cases cover that witness, classic config preference, duplicate/missing candidates, the prior M4 no-config shape and remote-mode no-call behavior. All five passed on Linux x64 and native M4 ARM64. Four actual Buildx load/tar/failure/cancellation cases passed on Linux Engine/CLI29.0.2 + buildx0.30.0 and M4 Engine/CLI29.9.3 + buildx0.38.1. Strict all-target Clippy passed on both. The real load test now verifies that the reported reference is addressable and resolves to the same image ID/size as the requested tag, accommodating valid config/index aliases rather than requiring literal identity strings. Tagless tar checks positive size before its intentionally temporary export tag is removed.

The corrected temporary static Linux ARM executable also passed all six complete workflow scenarios in default strict mode: real build reference/size equality, command/artifact/exit, Actions, two-worker JUnit shards, cancellation and doctor. Its exact executable and receipt are linked in `summary.json`. The parent additionally ran the complete corrected-source suite (247 passed, 32 explicitly ignored across 43 targets) and strict Clippy; those are source checks, not a claim that new common release bytes were already executed. Final common preview `native-preview-20261110-7c41b2f3c79d` is built and checked separately; historical cd6 bytes remain unchanged.

Mac checks used a disposable anonymous Docker config to avoid global keychain helpers. An initial private-config plugin discovery failure was corrected only by adding a private symlink to Docker.app's unmodified bundled Buildx. That private configuration was removed after checks. The user Docker config, keychain, Desktop state and unrelated resources were unchanged. The artifact logs contain no credentials.
